rsync vs scp 用法、优劣对比

scp：旧OpenSSH文件拷贝工具，官方标记废弃；rsync：增量同步工具，ssh作为传输底层，是替代首选。

一、基础用法

scp 语法

# 本地 → 远程
scp localfile user@host:/remote/path
# 远程 → 本地
scp user@host:/remote/file localfile
# 传目录（-r递归）
scp -r ./public user@host:/var/www/site
# 自定义ssh端口
scp -P 2222 ./public user@host:/var/www/site

-P 大写指定端口；-r 递归目录。

rsync over ssh 语法（推荐）

# 本地目录上传远端（黄金参数）
rsync -avz --partial --progress ./public/ user@host:/var/www/site/
# 远端下载到本地
rsync -avz --partial --progress user@host:/var/www/site/ ./public/
# 自定义ssh端口
rsync -avz --partial --progress -e 'ssh -p 2222' ./public/ user@host:/var/www/site/
# 预览（dry-run，不实际传输，强烈建议初次执行加）
rsync -avz --partial --progress --dry-run ./public/ user@host:/var/www/site/
  • -a archive：归档，保留权限、时间、属主、递归，最核心参数
  • -v verbose 详情；-z 传输压缩；--partial 中断保留已传部分，支持断点续传
  • --progress 显示进度条

⚠️ 目录末尾/非常关键：./public/代表目录内所有文件；./public代表把public整个文件夹传到远端。

二、优劣对比

项目 scp rsync (over ssh)
底层协议 老旧SCP协议（OpenSSH已弃用） ssh通道 + rsync自定义差分算法
增量传输 ❌ 全量拷贝，不管文件有没有改动 ✅ 差分校验，只传文件改动部分（Hugo发布巨大优势）
断点续传 ❌ 中断直接作废，全部重传 ✅ --partial 保留已接收部分，断线续传
文件属性 基础保留，不稳定 ✅ 完整保留权限、mtime、软链接
限速 无原生限速 ✅ --bwlimit=10M 限速10MB/s
删除远端文件 不能选择性清理 ✅ --delete 删除远端多余文件（慎用！适合hugo public同步）
远端依赖 只需要sshd，远端不用额外装软件 远端必须安装rsync
大量小文件 性能差 小文件场景也更优
公网稳定性 弱网容易失败 弱网更稳，支持续传
适用场景 一次性少量小文件应急 反复同步、网站发布、备份、大目录（hugo首选）

三、关键取舍场景

  1. ✅ 日常Hugo静态站点发布 → rsync 每次hugo构建后，只有改动的html/css/js会上传，节省流量和时间。
hugo && rsync -avz --partial --progress ./public/ user@ip:/var/www/site/

如果要远端自动清理旧文件（推荐生产），加上--delete，先跑一次–dry-run预览

rsync -avz --partial --progress --delete --dry-run ./public/ user@ip:/var/www/site/
  1. ✅ 远端服务器不能安装rsync → 放弃rsync，改用sftp/lftp 此时scp仅作临时应急，不推荐写进自动化脚本。

四、坑点

  1. scp 在新版openssh会输出警告：scp: warning: scp protocol is deprecated
  2. rsync的--delete非常危险：会删掉远端存在、本地不存在的文件，一定先dry-run
  3. rsync 两端rsync版本差距过大，偶尔会出现兼容性报错

一句话总结

  • 一次性少量文件、远端无法装rsync：临时用scp（不推荐自动化脚本）
  • 重复同步、Hugo发布、备份、大量文件：优先rsync
